# 설계 연혁

ADR 들은 각 결정의 근거를 담고 있지만, 그 결정들이 **어떤 순서로, 무엇을 고치면서** 나왔는지는 담고 있지 않다. 이 문서가 그 공백을 메운다.

목적은 기록 보존이 아니라 **재논의 방지**다. 아래 "버린 것"들은 그럴듯해 보이고, 맥락이 없으면 몇 달 뒤 처음부터 다시 검토하게 된다.

## 출발점과 현재

| | 최초 구상 | 현재 |
|---|---|---|
| 산출물 | AI 가 각국 보도를 종합해 **중립적·객관적 의견**을 도출 | 판정하지 않고 **차이를 드러내는 지도** |
| 대상 | 세계 주요 언론 (한·일 제외) | 같음, 단 **자국어판 우선** |
| 핵심 기능 | 중립 브리핑 | ① 노출 격차 ② 외부에서 본 안쪽 이슈 ③ 프레이밍 대조표 |
| 안쪽 언론의 위치 | 아예 배제 | 노출 격차의 분모 + **프레이밍 비교표의 한 행** |
| AI 의 역할 | 결론을 쓴다 | 주장과 출처를 추출한다. 결론은 쓰지 않는다 |

## 세 번의 방향 전환

전부 사용자 질문에서 나왔고, **세 번 다 같은 방향**이었다 — 제안된 설계가 요청받은 것보다 좁았다. 이 패턴 자체가 기록할 가치가 있다.

### 1. "일본도 한국처럼 취급하고 있죠?"

공백 판정 코드가 `probes.get("KR")` 로 한국만 보고 있었다. 문서에는 "한국·일본"이라 적혀 있었다. 더 나쁜 것은 데모에 일본 기사가 한 건도 없는데 출력에 `🇯🇵 미보도` 로 찍혔다는 점 — "일본도 안 다뤘다"처럼 읽히지만 실제로는 "데이터가 없었다"였다. **거짓 진술이 산출물에 들어가 있었다.**

→ `no_data` 판정 신설 (ADR 0005). 피드가 하루 고장났을 때 모든 사건이 공백이 되는 문제도 같이 막혔다.

### 2. "한국과 일본을 굳이 구분 안 해도 돼요"

이에 앞서 "두 언론을 다 보는 한 사람"이라는 점이 명확해졌고, AND 판정으로 고쳤다 (ADR 0005). 그런데 사용자는 더 나아가 국가 구분 자체가 불필요하다고 지적했다 — 어느 쪽이 다뤘는지가 아니라 **내가 접하기 쉬웠는지**가 문제이므로.

→ 안쪽을 하나로 합치고, 이진 판정을 **연속 격차**로 교체 (ADR 0006). 부수 효과로 AND/OR 논쟁이 애초에 사라졌다. 공들여 만든 AND 조건 하나가 불필요해졌다.

### 3. "그 바깥의 날것에 해당하는 세계의 정보를 접하자는 거죠"

결핍이 두 가지로 섞여 있었다는 지적. **누락**(아예 오지 않은 것)과 **굴절**(왔지만 안쪽 필터에 휘어서 온 것). 설계는 누락만 다루고 있었고, 더 나쁘게는 **굴절을 적극적으로 억제**했다 — 안쪽이 다룬 사건은 "공백 아님"으로 목록에서 떨어뜨렸는데, 굴절이 가장 심한 것은 정확히 크게 보도된 사건들이다.

→ ADR 0006 전체. '외부에서 본 안쪽 이슈' 섹션, 안쪽 프레이밍을 비교표의 한 행으로, 그리고 **소스를 자국어판 우선으로**.

## 버린 것 (다시 꺼내기 전에 읽을 것)

**"AI 가 종합 의견을 내준다."** 가장 자연스러워 보이는 설계이고, 최초 구상이었다. 버린 이유 세 가지: ① 20개 매체 논조의 평균은 중립이 아니라 무색무취이며 사안에 따라 왜곡이다 ② 영어권 웹으로 학습된 모델에게 중립 판정을 맡기면 눈에 보이는 편향을 눈에 안 보이는 영미권 편향으로 교체한다 ③ AI 가 생성한 "객관적 의견"은 반증이 불가능하다. 이 판단은 `README.md` 와 `CLAUDE.md` 에도 있고, 테스트가 기계적으로 강제한다.

**독자별 공백 목록 (한국 독자용 / 일본 독자용 분리).** 전환 2번 직전에 구현하던 것. 두 언론을 다 보는 한 사람에게는 틀렸다 — 일본어로 이미 읽은 기사가 목록을 채운다.

**OR 판정 (한쪽만 안 다뤄도 공백).** 같은 이유로 버렸으나, 사용자가 "모든 이슈를 다 보는 건 아니니까" 약한 신호로는 가치가 있다고 했다. 연속 격차(ADR 0006)가 이를 흡수했다 — 안쪽 1건은 0건보다 격차가 작지만 0은 아니다.

**손으로 쓴 대규모 다국어 별칭 사전.** 수천 개 고유명사 × 7~9개 언어. 작성자가 자신 없는 언어를 추측으로 채우게 되고(틀린 표기는 빈 표기보다 나쁘다), 인물 항목은 선거로 조용히 썩는다. → 시드 112개 + Wikidata 생성 (ADR 0003).

**영문판 중심 소스 목록.** 쉬웠기 때문에 초기 후보 30건이 영어로 기울어 있었다. Global Times English·TASS English·France24 English 는 외국인 독자용으로 이미 정제된 것이고, 그것만 읽으면 **국내 필터를 수출용 필터로 바꾸는 것**일 뿐이다. 이 프로젝트에서 가장 큰 단일 위협이었다. → `priority` 열 도입, native 38 / export 11 (ADR 0006).

**기존 저장소 `Neutralize4KRJP` 에 얹기.** 그 저장소는 한·일 2자 구조에 묶여 있고 시점이 박혀 있다. 계승한 것은 코드가 아니라 설계 판단 세 가지 — 구조화 출력, 파이프라인/UI 분리, 비용 0 테스트. 버린 것은 "LLM 이 중립 결론을 쓴다"는 전제. 그 저장소 README 의 "중립성을 측정하지 않았습니다"가 이 프로젝트의 출발점이다.

## 정직한 천장 (ADR 0006 에서 재확인)

이 도구는 필터를 **제거하지 못한다. 하나 더 추가한다.** 주장할 수 있는 것은 둘뿐이다. ① 원어 단어를 그대로 보여준다 ② 어디서 갈라지는지 알려준다. 즉 **날것 자체가 아니라 날것으로 가는 색인**이다. 모든 항목에 원문 링크가 붙는다.

그리고 제목+리드는 얇은 층이며 제목은 기사에서 가장 편집된 부분이다. RSS 기반 "날것"은 약한 날것이다.

## 아직 열린 것

**측정 수단이 없는 것.** 무엇을 보여줄지 **고르는 단계의 편향**. M2 는 한 클러스터 안의 앵글로권 과대 인용은 재지만, 어떤 클러스터가 상위에 뽑히는지는 재지 않는다. 뚫린 구멍으로 남아 있다.

**사용자 판단이 필요한 것.** ADR 0001 의 질문 4개 — Guardian API 가 본문까지 주면 어떻게 할지, GDELT 를 대체로 쓸지 보완으로 쓸지, 국가통제 매체 비율 상한, latam·africa 소스 확보.

**측정하지 않은 것.** 전부. 모든 임계값이 미보정이고 소스 조사는 0% 다. 클러스터링 품질은 교차언어 사건 식별이라 60~75% 쯤을 예상하지만 그것도 추정이다. 노출 격차를 공개 지표로 쓰기 전에 하루치 50개 클러스터를 손으로 라벨링해 정밀도를 내야 한다 (`eval/gap_calibration.py`).

**일정 추산 (파트타임 1인 기준, 미검증).** Phase 0 1~2일 / Phase 1 실제 결합 1.5~3주 / 보정 1주 / Phase 2 1~2주 / Phase 3 1주 / Phase 4 3~5일. 시간을 먹는 곳은 플러밍이 아니라 클러스터링 임계값 조정이다.

**가장 큰 실패 요인.** ① 자국어판 피드를 못 구함 — Phase 0 가 먼저인 이유 ② 클러스터링 품질 ③ 피드는 조용히 죽으므로 유지보수 소진. 비용·규모·법적 리스크는 아니다.

## 선행 작업

[Ground News](https://ground.news), AllSides 는 **한 나라 안의 좌-우** 비교다. 이 프로젝트는 **국가 간** 비교와, 한국어·일본어 사용자 기준의 노출 격차, 그리고 **외부에서 본 안쪽 이슈** 를 다룬다. 마지막 것이 가장 확실하게 비어 있는 자리다 — 언어 장벽이 가장 두껍고, 기술적으로는 가장 쉽다 (별칭 사전이 이미 개체를 추출한다).
